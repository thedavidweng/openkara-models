# OpenKara spectral contract — `openkara.spectral-contract/v1`

The exact waveform↔spectral transform semantics of the shipped HTDemucs
graphs (issue #23 PR 1). The shipped ONNX models implement these transforms
with dense conv1d/conv_transpose1d DFT matrices (~134 MB of constants per
model); this contract lets OpenKara implement them natively (FFT) so the
spectral-core models of issue #23 can drop those constants. The reference
implementation is `scripts/spectral_reference.py` (pure numpy, float64);
golden vectors are generated by `scripts/generate_spectral_golden_vectors.py`
and pinned by digest in `quality/spectral-golden-v1.json`.

## Constants

| Name | Value | Meaning |
|---|---|---|
| `sample_rate` | 44100 | Hz |
| `channels` | 2 | stereo |
| `segment_frames` | 343980 | fixed inference window (7.8 s) |
| `n_fft` | 4096 | FFT size |
| `hop` | 1024 | hop length (= n_fft/4) |
| `window` | periodic Hann | `sin²(π·n/4096)`, n = 0..4095 (torch default; NOT the symmetric variant) |
| `contract_freqs` | 2048 | one-sided bins carried (Nyquist bin dropped) |
| `outer_pad` | 1536 | Demucs outer reflect padding (= hop/2·3) |
| `envelope_clamp` | 1e-8 | ISTFT overlap-add envelope floor |
| `norm` | 1/√4096 | applied in BOTH directions (`normalized=True`) |

For the fixed window: `le = ceil(343980/1024) = 336` frames; the spectral
tensor is `[B, 2, 2, 2048, 336]`.

## Forward: waveform → spectral tensor (`spec`)

Input `x` `[B, 2, samples]` float32.

1. `le = ceil(samples / hop)`.
2. Reflect-pad the last axis: `outer_pad` left, `outer_pad + le·hop − samples` right.
3. STFT with center padding (`n_fft/2` reflect on both sides inside the
   transform), periodic Hann window, one-sided output (2049 bins),
   scaled by `1/√n_fft`. Imaginary convention: `e^{−i2πkn/N}` — the
   imaginary part uses **−sin** (matches `torch.stft`).
4. Drop the Nyquist bin: keep bins `0..2047`.
5. Crop frames `[2 : 2+le]` (the STFT of the padded signal has `le+4` frames).
6. Layout: `(batch, channel, {real,imag}, freq, frame)`, contiguous.

## Neural-core view (`magnitude` / `mask`, cac=true)

- Core input view: `[B, 2, 2, F, T]` → reshape → `[B, 4, F, T]`
  (channel-major: `[L_re, L_im, R_re, R_im]`).
- Core output view: `[B, S, 4, F, T]` → reshape → `[B, S, 2, 2, F, T]`.
- **Normalization stays inside the exported core**: the core normalizes the
  magnitude view by its own mean/std over `(channel, freq, frame)` and the
  time-branch input by mean/std over `(channel, sample)`, then de-normalizes
  outputs. Note: std is the UNBIASED (N−1) standard deviation with `1e-5`
  added before division. Applications never implement these statistics.

## Inverse: spectral tensor → waveform (`ispec`)

Input `z` `[B, S, 2, 2, 2048, T]`, target `length`.

1. Re-append a zero Nyquist bin (→ 2049 bins).
2. Zero-pad two frames on each side (→ `T+4` frames).
3. One-sided inverse DFT per frame: `y_t[n] = Σ_k scale_k·(Re_k·cos(2πkn/N)
   − Im_k·sin(2πkn/N))·w[n]/√N` with `scale_k = 2` for `0 < k < 2048`,
   `scale_k = 1` for `k ∈ {0, 2048}`.
4. Overlap-add with stride `hop`; divide by the window envelope
   `Σ_t w²[n − t·hop]` clamped at `envelope_clamp`.
5. Crop `n_fft/2` samples from the front, then to
   `le' = hop·ceil(length/hop) + 2·outer_pad` samples.
6. Final crop `[outer_pad : outer_pad + length]`.

## Spectral-core model boundary (issue #23 PR 2)

The exported core has **two inputs and two outputs** (HTDemucs is hybrid):

| Tensor | Shape | Producer |
|---|---|---|
| in: `spectral` | `[B, 2, 2, 2048, 336]` | app `spec(mix)` |
| in: `mix` | `[B, 2, 343980]` | app (time branch input) |
| out: `spectral_out` | `[B, 4, 2, 2, 2048, 336]` | core (pre-ISTFT, de-normalized) |
| out: `time_out` | `[B, 4, 2, 343980]` | core (time branch, de-normalized) |

Application composition: `stems[s] = ispec(spectral_out[:, s], 343980) + time_out[:, s]`.

Karaoke optimization (linearity): `accompaniment = ispec(Σ_{s∈{drums,bass,other}}
spectral_out[:, s]) + Σ time_out[:, s]` — one ISTFT instead of three.

## Reconstruction validity and tolerances (measured)

- **Nyquist**: content at bin 2048 (22050 Hz) is discarded by the forward
  transform and reconstructed as zero. Broadband signals leak ~−80 dB of
  Hann-windowed energy into that bin, bounding broadband round-trip error
  near `1e-4` max-abs; band-limited content round-trips to `≤1e-8`.
- **Edges**: the first and last `n_fft` (4096) samples of a reconstructed
  window lose overlap-add contributions from the cropped frames
  (interior error `~1e-10`; transition band up to `~3e-6`). Segment
  stitching in the application MUST overlap at least 4096 samples per side
  and cross-fade so only interior samples are used. This applies to the
  CURRENT shipped waveform models identically.
- **Implementation tolerance**: the shipped fp32 conv-DFT graphs deviate
  from the float64 reference by (measured, 0.3-RMS input):
  `stft ≤ 2.4e-4`, `istft ≤ 9e-5`, `spec ≤ 2.3e-4`, `ispec ≤ 1e-4` max-abs.
  A conforming native implementation must stay within `1e-3` max-abs of the
  reference per stage on the golden vectors (fp32 budget), `1e-6` if it
  computes in float64.

## Golden vectors

`scripts/generate_spectral_golden_vectors.py` deterministically produces,
for each fixture (silence, impulse, tone, sweep, band-limited noise,
hop-aligned and unaligned lengths): the input wave, the spectral tensor, the
magnitude view, and the identity round-trip reconstruction, as float32
`.npz`. `quality/spectral-golden-v1.json` pins every array's SHA-256; CI
regenerates and diffs. The `.npz` bundles are published as release assets
(tag `spectral-golden-v1`) for the native implementation to test against.

## Versioning

This contract is `openkara.spectral-contract/v1`. Spectral-core model
artifacts (issue #23 PR 2+) must carry the contract version in model
metadata (`openkara.spectral_contract`) and in their catalog entries. Any
semantic change (constants, layouts, padding, normalization ownership,
tolerances) requires `/v2` and new golden vectors.
